## Compito D — Protezione del ramo su GitHub (decisione del titolare, D-24)

### Che cosa copre la protezione del ramo su GitHub
- **Blocco dei push forzati (`force-push`):** impedisce di riscrivere o cancellare commit già spinti su GitHub (ferma sul remoto l'attacco `#98`, `B2.4`).
- **Blocco della cancellazione del ramo:** impedisce di far sparire un ramo su cui è registrata una verifica o un'apertura della riserva.
- **Controlli di stato obbligatori (*required status checks*):** impone che `suite (3.13)` e `suite (3.9)` di `.github/workflows/test.yml` siano verdi prima del merge (nota tecnica: `paths-ignore: ["**/*.md"]` è oggi solo su `push`, non su `pull_request`, quindi le PR fanno comunque partire i check; se fosse su `pull_request`, le PR solo `.md` resterebbero bloccate).
- **Revisione obbligatoria / `CODEOWNERS`:** impedisce a un agente o contributore di modificare silenziosamente `.github/workflows/test.yml`, `.github/scripts/esegui_test.py`, il perimetro sigillato o i registri senza approvazione esplicita del titolare (mitiga `B7.1` e `B7.2`).
- **Timestamp e audit log server-side:** GitHub registra chi e quando ha spinto o fuso un commit, rendendo visibili eventuali date commit retrodatate (`B2.6`).

### Che cosa NON copre
- **Repository e registri locali prima del push (`#90`):** chi ha accesso alla shell locale può ancora scrivere un file JSON coerente ma falso prima di committarlo e spingerlo.
- **Riscrittura locale di `refs/remotes/origin/...` e del reflog (`#98`) senza `git fetch` dal remoto:** finché un comando gira solo in locale a rete bloccata, non interroga GitHub; l'inganno viene però smascherato al primo `git fetch` o `git push` verso il ramo protetto.
- **Manomissione locale di `avvio.py` / esecuzione diretta `python3 -c`:** il codice eseguito sul Mac resta responsabilità dell'operatore finché non viene verificato/riprodotto.
- **Alterazione locale della cache `.bi5` prima dello sviluppo (`R18-02`, `R18-05`):** la cache Dukascopy non è su GitHub (regola dei dati reali fuori dal repo).
- **Bypass dell'amministratore:** su GitHub il proprietario del repository può scavalcare le regole se non è attiva l'opzione *Do not allow bypassing the above settings* (*Include administrators*).
